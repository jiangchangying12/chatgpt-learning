Part 1–2 綜合實戰

觀念陷阱與
應用驗收

100 分不一定等於能應用。這一章刻意拿掉明顯錯誤選項，改用「每個選項看似都有道理」的真實情境，檢驗你是否能把概念轉成工作判斷。

真正通過標準
85 分 + 實作

20 題情境題達 85 分，四項能力均達 70%，並完成至少一個可觀察的實作任務。

建議不要查教材；作答時記下每題理由，再對照解析。

01｜為什麼兩次 100 分仍可能不踏實？

辨識不等於回想

看到明顯正確選項，是辨識能力；沒有選項時能自己提出做法，才是回想與應用。

概念不等於遷移

知道 Search 適合最新資料，不代表遇到「最新資料 + 內部 PDF + 選型報告」時會正確組合工具。

答對不等於理由正確

可能靠關鍵字猜中。這次請先說出理由，再選答案。

測驗不等於工作證據

真正吸收要留下成果：澄清問題、來源策略、風險表、驗收條件或可用成品。

作答規則：每題先在紙上或記事本寫一句「我為什麼選它」。答對但理由與解析不同，仍應視為需要複習。

02｜六個實用案例：從需求判斷到驗證

案例 1｜需求書衝突

內部 PDF + 會議紀錄

核准規格 v3 與昨天會議紀錄衝突。不要叫 AI 自行選「較新」的內容。

① Files：辨識衝突位置
② Context：定義 v3 為核准基準
③ 輸出：待確認表，不擅自合併
列出衝突內容、影響範圍、需決策人與截止時間。
未經確認，不修改核准需求。
案例 2｜最新技術選型

.NET + PostgreSQL 升級

既需要官方最新資訊，也要結合內部相容性清單。

① Search：官方 release notes
② Files：內部套件與部署限制
③ Reasoning：差異與風險映射
外部事實逐項附官方來源；內部限制標明文件位置；
推論與事實分欄，不把建議寫成已證實結論。
案例 3｜錯誤診斷

偶發 PostgreSQL timeout

不要先要求「給我最佳修正碼」。先建立假設與證據計畫。

① Context：log、metrics、版本、發生條件
② Thinking：列假設與可區分證據
③ Work：安全地檢查與測試
先產生「假設—支持證據—反證—下一個安全檢查」表。
資訊不足時停止，不直接改 production 設定。
案例 4｜法規與內規

個資保存期限

高風險且會變動，不能只靠模型，也不能只看一篇網路文章。

① Search／Research：官方法規來源
② Files：機關內規與契約
③ 人工：法務／權責單位確認
AI 負責找來源、比對與列問題；最終法律判斷及核准
保留給具權責的人員。
案例 5｜交付成品

需求追蹤矩陣

回答一張 Markdown 表格不等於完成可維護的追蹤矩陣。

① 定義欄位與 ID 規則
② 建立 Spreadsheet 成品
③ 驗證每項需求、測試與狀態映射
完成標準：無重複需求 ID、每項需求至少一個驗收案例、
未對應項目自動標示。
案例 6｜模糊需求

「做一套案件系統」

最成熟的第一步通常不是完整架構，也不是立即寫 code。

① 找出會改變設計的未知事項
② 依風險排序詢問
③ 確認後產生最小草案
一次只問最重要的問題；每題說明若不確認會造成什麼
設計或驗收風險。

03｜三個可觀察實作：證明你真的會

實作 A｜15 分鐘：不看教材，設計工作流程

情境：你有一份內部系統規格 PDF，要評估升級到目前最新 .NET 與 PostgreSQL 的影響。自行寫出完整工作流程。

必須包含：資料來源分類、工具順序、Prompt 第一輪、哪些結論需來源、哪些需測試、停止條件與最終成品。

實作 B｜20 分鐘：改寫一個危險 Prompt
幫我看需求書，查最新最佳實務，直接設計完整系統，
把不合理需求修好並產生程式碼。

把它拆成至少三輪。每輪都要有輸入、成果、限制和驗證；不得允許 AI 自行修改核准需求。

實作 C｜30 分鐘：ASP.NET Core + PostgreSQL

設計案件狀態更新功能，但先不寫完整 code。交付：7 個澄清問題、狀態轉換表、API contract、稽核資料模型、並行更新策略、8 個測試案例與 3 個待人工決策事項。

自評方法：能產出只是 60%；若成果清楚區分「來源事實、合理假設、待確認、建議」，並有驗證與停止條件，才算真正吸收。

04｜20 題觀念陷阱測驗

題目涵蓋四個面向，每題 5 分。選項刻意設計得相近；請選「當下最合理的第一步或做法」，不是選任何可能有幫助的做法。

05｜通過標準：不要只看總分

條件代表意義
總分 ≥ 85多數混合情境能選出合理工作方式。
每個能力軸 ≥ 70%不是靠某一類題目拉高總分。
完成至少一個實作能在沒有選項提示時自行產出流程。
能解釋錯題知道其他選項不是永遠錯，而是此時順序或風險不合理。
最嚴格的吸收判定：隔 48 小時、不看教材，再完成另一個相似但不同的情境。如果仍能建立正確流程，才代表知識已能遷移。
