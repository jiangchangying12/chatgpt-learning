把答案變成可交付成果

文件、試算表、簡報與圖片不是同一份內容換副檔名。你要從使用者、任務與維護方式選媒介，再以內容、結構、計算與視覺四層 QA 驗收。

完成標準
85 分 + 成品

能選對交付格式、寫出成品規格、完成至少一項真實產出，並提供可重現的 QA 證據。

預估學習 60 分鐘；實作 45–90 分鐘。

02｜不是哪個格式最好，而是哪個最適合使用

成果最適合不適合當唯一成果
Word／文件正式說明、章節敘事、審查修訂、列印需要大量計算、篩選或即時簡報
Excel／試算表結構資料、公式、追蹤、篩選、圖表長篇論證與正式排版報告
PowerPoint／簡報口頭報告、決策溝通、逐頁敘事完整細節、逐條規格與可搜尋資料庫
PDF固定版面、正式傳閱、跨裝置一致呈現後續協作編輯與資料重算
圖片情境視覺、插圖、概念氛圍、宣傳素材精確流程、數值圖表、細小文字
視覺化／圖表比較、趨勢、關係、流程與互動探索沒有數據或關係、只為裝飾的場合
實務上常是組合：主管簡報 + 完整 Word 報告 + Excel 附表，比要求一份簡報同時承擔所有細節更合理。

03｜把 Prompt 寫成「成品規格」

內容契約

目標、讀者、資料來源、必含章節、不可自行添加的資訊。

格式契約

檔案類型、頁數、欄位、版面、比例、字體與可編輯性。

驗收契約

正確性、完整性、公式、版面、連結、列印及交付檢查。

根據已核准的需求分析，建立「需求追蹤矩陣.xlsx」。
讀者：系統分析師、開發與驗收人員。
工作表：需求、API、測試案例、追蹤總覽。
必須使用穩定需求 ID；每項需求至少對應一個測試案例。
用公式產生覆蓋率，不要手填計算結果。
未對應需求以條件格式標紅。
產生後重新計算並檢查：公式錯誤、重複 ID、空白必要欄位、
跨表引用、篩選與凍結窗格。

04｜四層 QA：可打開只是最低標準

QA 層檢查內容證據
內容事實、引用、需求覆蓋、邏輯一致來源對照、缺漏清單
結構章節、欄位、層級、導航、可維護性大綱與 schema 檢查
功能公式、圖表、連結、互動、可編輯性重算結果、錯誤掃描
視覺截斷、溢位、對齊、字級、對比、列印逐頁渲染或預覽

試算表

  • 公式不是硬編數值
  • 重新計算後無錯誤
  • 圖表來源範圍正確
  • 欄位格式與單位一致

文件／PDF

  • 標題層級與目錄正確
  • 表格不跨頁破裂
  • 頁首頁尾與頁碼一致
  • 渲染後無空白孤頁

簡報

  • 一頁一個主要訊息
  • 投影距離仍可閱讀
  • 圖表支援結論
  • 備註承載口頭細節

圖片

  • 用途與尺寸明確
  • 不要依賴生成圖呈現精確文字
  • 品牌、權利與敏感內容檢查
  • 必要時保留透明背景

05｜六個實用案例

政府專案週報

一份資料，兩種受眾

Excel 保留任務明細、工時與風險；PowerPoint 只呈現決策、紅燈項目與趨勢。不要把完整試算表縮小貼進投影片。

需求審查

Word 主報告 + Excel 追蹤

Word 說明矛盾與影響；Excel 管理每項問題的 ID、責任人、狀態、期限和需求／測試映射。

系統架構

精確圖不用生成圖片

流程、元件與資料流應用可精確修改的圖表或程式化圖形；生成圖片適合封面或概念情境，不適合精確拓撲。

水情趨勢

先決定問題，再選圖表

時間趨勢用折線；測站比較用長條；異常分布可能用散點。不要因為能畫圓餅圖就使用圓餅圖。

驗收文件

先定義完成證據

除了產出 PDF，還要保留可編輯來源、版本、來源資料與渲染檢查，避免只有無法維護的最終檔。

教育教材

內容與互動一起設計

HTML 適合導航、展開答案與自動計分；PDF 適合離線列印。依使用方式選擇，不是只依製作方便。

06｜實作：政府資訊專案月報套件

以同一份專案資料產出三個互補成果：

  1. 月報.docx：摘要、里程碑、風險、變更與下月計畫。
  2. 追蹤表.xlsx：任務、需求、測試、風險與公式化 KPI。
  3. 主管簡報.pptx：8–10 頁，只呈現需理解與決策內容。

驗收

  • 三份成果使用相同 ID 與統計口徑。
  • 數字可追溯到試算表，不手動複製不同結果。
  • 文件與簡報逐頁渲染檢查。
  • 試算表重新計算並掃描公式錯誤。
  • 列出資料截止日、假設、待確認與版本。
真正吸收的證據：你能說明為什麼每項資訊放在某一格式，並證明不同成果之間沒有數字漂移。
