01｜這一章真正要學的是什麼？

概念 1

不是學 Prompt 咒語

Prompt 很重要，但「選錯工作方式」比「Prompt 少寫一句」更容易讓結果變差。

概念 2

先辨識任務類型

回答知識、查最新資料、研究多來源、分析檔案、建立成品、跨工具執行，是不同任務。

概念 3

把 ChatGPT 當工作環境

對話只是入口；價值來自推理、搜尋、檔案、研究、外部工具與產出能力的組合。

03｜ChatGPT 的 5 層心智模型

層級要問自己的問題例子
1. 對話層只是解釋、整理、腦力激盪嗎？解釋 PostgreSQL MVCC
2. 推理層需要規劃、比較、除錯、設計嗎？比較三種同步架構與 trade-off
3. 資訊層依賴現在的網路資料或很多來源嗎？Search / Deep Research
4. Context 層需要 PDF、Excel、程式碼或外部資料嗎？規格書、系統文件
5. 行動／產出層只是答案，還是把工作做完？建立表格、文件、工作流
常見誤區：把所有需求都塞成一個超長 Prompt。更好的方式通常是：定義成果 → 給 Context → 選模式／工具 → 第一輪 → 檢查與迭代。

05｜實際案例：先選方法，再寫 Prompt

容易犯的錯

我要了解 SDD

請完整告訴我什麼是 SDD，並說明所有最佳實務。

若問的是近期實務、工具生態或趨勢，只靠既有知識可能不夠。

較佳思路

拆成知識 + 現況

先建立 SDD 核心概念。
再搜尋近期可靠來源確認主流做法。
最後整理成 .NET 團隊可實踐流程。

分析自己的規格書

這是我的需求規格書。不要先摘要；先找：
1. 需求矛盾
2. 缺少驗收條件
3. 非功能需求缺口
4. 可能影響 DB Schema 的需求
最後產生待確認清單。

判斷：Files + reasoning，不是先 Search。

查 PostgreSQL 最近版本變化

查目前 PostgreSQL 最新穩定版本。
只使用官方文件與 release notes，
整理對現有 .NET Web API 最可能有影響的 5 項變化。

判斷：「目前、最新」→ 使用最新資訊來源。

技術選型報告

研究 PostgreSQL 高可用架構主流方案，
比較可維運性、RTO/RPO、成本、綁定與資安，
需要來源與可追溯結論。

判斷：多來源、需要證據 → Deep Research。

06｜第一個操作練習

15 分鐘挑戰

簡易案件追蹤系統

背景：ASP.NET Core Web API + PostgreSQL；案件建立、承辦人、狀態、處理紀錄、附件、查詢。

  1. 先列出實作前缺少的需求。
  2. 回答最重要的 5 個問題。
  3. 提出資料模型與 API 草案。
  4. 指出草案最可能出錯的 3 個地方。
  5. 最後才產生一個 endpoint 與測試。
我要規劃一個 ASP.NET Core + PostgreSQL 的案件追蹤系統。
先不要寫程式。
請從系統分析與實作者角度，找出會影響資料模型、API、安全性與驗收測試的關鍵缺口。
一次只提出最重要的 5 個問題。

07｜吸收測驗

Q1. 解釋資料庫正規化，需要先 Search 嗎？

顯示答案

通常不需要。這是穩定基礎知識。

Q2. 「目前 .NET 最新 LTS 版本？」

顯示答案

需要最新資訊。應搜尋並優先確認官方來源。

Q3. 150 頁需求書找矛盾，第一優先 Deep Research？

顯示答案

不是。先 Files + reasoning；需要外部標準時再加 Search / Deep Research。

Q4. Search 與 Deep Research 最簡單差別？

顯示答案

Search 偏快速取得最新資訊；Deep Research 偏多來源、整合、引用與深入研究。

Q5. 為什麼超長 Prompt 不一定最好？

顯示答案

品質還取決於資訊來源、工具、上下文與產出方式；複雜任務更適合分階段迭代。
